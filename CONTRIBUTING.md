# Contributing

Thanks for your interest in Rubato Waveform Generator. Bug reports, feature ideas and pull requests are welcome. Please use the issue templates when you open an issue, and include your operating system, the app version and the FFmpeg version.

## Development setup

You need Python 3.12 or newer and FFmpeg with the `prores_ks` encoder.

```sh
git clone https://github.com/VukoP/rubato-waveform-generator.git
cd rubato-waveform-generator
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt && pip install -e .
python -m rubato_waveform.app
```

On Windows, activate the environment with `.venv\Scripts\activate`. CI runs Python 3.13 on Windows because it is the known-good combination with pythonnet.

## Running the tests

```sh
pytest                  # everything
pytest -m "not ui"      # skip the browser-driven UI tests
ruff check .            # lint
```

CI runs `ruff check .`, the non-UI tests on Linux, macOS and Windows, and the UI tests on Linux.

The UI tests drive the interface with Playwright, so they need browsers: `playwright install chromium webkit`. The `RUBATO_UI_BROWSERS` environment variable limits which browsers run. CI sets `RUBATO_UI_BROWSERS=chromium`. A browser that is not installed or not enabled is skipped.

## Project layout

- `rubato_waveform/engine.py`: audio analysis, shaping and frame drawing, and the FFmpeg encode.
- `rubato_waveform/cli.py`: the `rubato-waveform` command.
- `rubato_waveform/ffmpeg_tools.py`: finding FFmpeg and ffprobe, and the input allow-list.
- `rubato_waveform/catalog.py`: labels, ranges, presets and validation of untrusted input.
- `rubato_waveform/settings.py`: remembered settings.
- `rubato_waveform/session.py`: the state of one app session: loaded audio, preview frames, export.
- `rubato_waveform/server.py`: the local HTTP server behind the interface.
- `rubato_waveform/app.py`: the native window, built on pywebview.
- `rubato_waveform/ui/`: the HTML, CSS, JavaScript and fonts of the interface.
- `packaging/`: macOS and Windows build scripts.
- `scripts/`: generators for demo audio, brand assets and media, and the changelog extractor.
- `tests/`: unit, integration and UI tests, plus the golden frames in `tests/golden/`.

## Keeping rendering stable

Golden tests render a fixed matrix of frames from synthetic audio (layouts, styles, sizes, slider extremes, the preview path) and compare each frame's SHA-256 hash with `tests/golden/manifest.json`. A change that alters pixels is caught even when it looks harmless.

Exact frame hashes depend on libm and Pillow, so they are only compared on macOS arm64 with the Pillow and numpy versions the manifest was captured with, and never when the `CI` environment variable is set (exact hashes are checked on the maintainer's machine). Elsewhere those comparisons are skipped, and only the constants (layout, style and theme lists) are checked. If you are on another platform, ask a maintainer to regenerate the manifest, or say so in your pull request.

To regenerate the manifest, capture one run with numpy and one without, then merge them. From the repository root, with the pinned dependencies installed:

```sh
python tests/golden/capture.py --engine rubato_waveform/engine.py --out /tmp/numpy.json
python tests/golden/capture.py --engine rubato_waveform/engine.py --no-numpy --out /tmp/no_numpy.json
python tests/golden/capture.py --merge /tmp/numpy.json /tmp/no_numpy.json --out tests/golden/manifest.json
```

A pull request that changes the manifest must explain why the rendering is supposed to change. Unexplained golden changes will not be merged.

## Demo audio and media

Demo audio must be synthetic. Never commit real recordings, voices or music. `python scripts/make_demo_audio.py --out demo.wav --seconds 5` generates a deterministic demo WAV.

Brand assets and the media used by the README and the website are generated by scripts, not edited by hand:

- `python scripts/make_brand.py` writes `assets/brand/` (icons, mark, social preview).
- `python scripts/make_media.py` writes `docs/media/` from synthetic audio.

Change the script and regenerate rather than committing a hand-edited image.

## Pull requests

- Keep each pull request focused on one change.
- Add or update tests for behavior you change, and make sure `ruff check .` and `pytest -m "not ui"` pass.
- Update `CHANGELOG.md` under a new `[Unreleased]` heading when the change is visible to users.
- Do not add runtime dependencies without discussing them in an issue first.
- Do not bundle FFmpeg or other third-party binaries.
- Workflows stay hardened: actions pinned to full commit SHAs, read-only permissions, hosted runners only. A repository test enforces this.
- Report security problems privately, as described in [SECURITY.md](SECURITY.md), not in a public issue.
